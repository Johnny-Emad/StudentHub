# Configuration

Runtime configuration for StudentHub. All values live in `.env` (copied from `.env.example`); framework defaults live in `config/`.

---

## Application

| Variable | Default (`.env.example`) | Purpose |
|---|---|---|
| `APP_NAME` | `Laravel` | Application name. **Change to `StudentHub`** — it is used in mail headers and Vite. |
| `APP_ENV` | `local` | Environment (`local`, `production`, …) |
| `APP_KEY` | *(empty)* | Generated by `php artisan key:generate` — required for encryption/sessions |
| `APP_DEBUG` | `true` | Show stack traces. Set `false` in production |
| `APP_URL` | `http://localhost:8000` | Base URL used in generated links |
| `APP_LOCALE` / `APP_FALLBACK_LOCALE` | `en` | Localization |

## Database

| Variable | Default | Purpose |
|---|---|---|
| `DB_CONNECTION` | `mysql` | **MySQL 8.0+ is the supported engine.** `config/database.php` falls back to `sqlite` only if this variable is unset entirely |
| `DB_HOST` / `DB_PORT` | `127.0.0.1` / `3306` | MySQL server location |
| `DB_DATABASE` | `studenthub` | Schema name |
| `DB_USERNAME` / `DB_PASSWORD` | `root` / *(empty)* | Credentials |

The MySQL connection uses `utf8mb4` / `utf8mb4_unicode_ci` with `strict` mode enabled (`config/database.php`).

> **SQLite note:** `phpunit.xml` forces `DB_CONNECTION=sqlite` + `DB_DATABASE=:memory:` for the test suite only. SQLite is a test convenience, not a supported development database — migrations use MySQL-oriented constructs (e.g., `enum`, `unsignedTinyInteger`) that behave differently or fail on SQLite.

## Session, Cache, Queue

| Variable | Default | Purpose |
|---|---|---|
| `SESSION_DRIVER` | `database` | Sessions stored in the `sessions` table |
| `SESSION_LIFETIME` | `120` | Session lifetime in minutes |
| `CACHE_STORE` | `database` | Cache stored in `cache` / `cache_locks` tables. Statistics and dashboard queries rely on `Cache::remember` — see [modules/statistics.md](../modules/statistics.md) |
| `QUEUE_CONNECTION` | `database` | Jobs stored in `jobs` table (the app currently dispatches no queued jobs) |
| `FILESYSTEM_DISK` | `local` | Local disk under `storage/app` |

## Mail

| Variable | Default | Purpose |
|---|---|---|
| `MAIL_MAILER` | `log` | Emails are written to `storage/logs/laravel.log` instead of being sent. Password-reset and verification emails therefore never leave the server in local dev |

## Seeding

| Variable | Purpose |
|---|---|
| `SEED_TEACHER_PASSWORD` | Optional override for the password assigned to all 50 seeded teacher accounts (`TeacherSeeder`). Defaults to `password` |

> `AdminSeeder` does **not** read credentials from `.env` — the admin email and password are hardcoded in `database/seeders/AdminSeeder.php`. This is a known security issue; see [project-status.md](../project-status.md).

## Cache keys used by the application

| Key | TTL | Written by |
|---|---|---|
| `dashboard.stats` | 60 s | `DashboardController` |
| `dashboard.recent_students` | 60 s | `DashboardController` |
| `stats.subjects` | 300 s | `SubjectStatisticsController` |
| `stats.classes` | 300 s | `ClassStatisticsController` |
| `stats.grades` | 300 s | `GradeStatisticsController` |
| `stats.school.{md5(from\|to)}` | 300 s | `SchoolStatisticsController` — one key per date-range combination |

There is **no cache invalidation** anywhere in the codebase: after adding a student, exam, or grade, statistics can be stale for up to 5 minutes (300 s) and the dashboard for up to 60 s. Run `php artisan cache:clear` to flush manually.
